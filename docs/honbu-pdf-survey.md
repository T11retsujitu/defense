# 防衛装備庁 本部一般調達(PDF)の対応検討 (次期スコープ調査)

調査日: 2026-08-15

## 対象

防衛装備庁 長官官房会計官による契約情報の公表(中央調達以外の本部一般調達)。

- 掲載ページ: https://www.mod.go.jp/atla/data/info/ny_honbu/ny_honbu_ichi.html
  (中央調達と同じくHTMLは機械取得不可)
- ファイルURL規則(実ファイルで確認):
  `https://www.mod.go.jp/atla/data/info/ny_honbu/pdf_ichiran/r{YY}/{YY}-{ekimu|buppin?}-{kyousou|zuikei}-h-{NN}.pdf`
  例: `r07/07-ekimu-kyousou-h-01.pdf`, `r07/07-ekimu-zuikei-h-01.pdf` (いずれも200 OK)
- 関連機関別に同型のディレクトリが存在する(例: `ny_kenkyu_shinsedai/pdf_ichiran/r07/...`
  = 次世代装備研究所)。地方防衛局・各自衛隊も同様の様式で公表している。

## 形式 (サンプル2ファイルの実測)

- **PDF**(罫線付き表、電子生成でテキスト抽出可能。スキャン画像ではない)
- 様式は中央調達xlsxと同じ「公共調達の適正化(財計第2017号)」付紙様式
  - 列: 件名及び数量 / 契約担当官 / 契約締結日 / 相手方商号・住所 / **法人番号** /
    根拠条文・理由(随契) / 予定価格 / 契約金額 / 落札率 / 備考
- 中央調達xlsxとの差異:
  - 契約締結日が **和暦文字列**(例: `R8.1.7`) — 既存の`parse_date`で対応可能
  - セル内改行が多く、`pdftotext -layout` では列の再構成が困難
  - 予定価格に「同種の他の契約の予定価格が類推されるおそれがあるため公表しない。」等の
    長文注記が入る

## 実装方針(提案)

- 抽出は `pdfplumber`(lattice=罫線ベースのテーブル抽出)を使う。罫線があるため
  実装可能と判断。ただしxlsxと比べ以下のコスト増:
  - ページ跨ぎの行分割・セル内改行の復元
  - ファイルごとのレイアウト微差の吸収
  - 抽出誤りの検知(合計値・列数の検証)が必須
- スキーマは現行のまま収容可能: `sources.organization` に部局名、
  `raw_contracts` は同一列構成。`agency` の正規化値を「防衛装備庁(本部一般調達)」等に分ける。

## 判断

**PoC本体には含めず、次期フェーズとする。**

理由:
1. 中央調達xlsxに比べ、金額規模が小さい契約(役務・庁費類)が中心で、
   産業データベースとしての情報価値の増分が相対的に小さい。
2. PDF表抽出は誤抽出リスクがあり、検証機構(行数・金額合計の照合、
   目視サンプリング)の整備とセットで導入すべき。
3. 同型式のPDFは地方防衛局・各自衛隊にも展開されており、
   一度パーサを整備すれば横展開できる。優先順位を付けて一括設計する方が効率的。

先行して着手する場合の最小ステップ:
`pdfplumber`でr07のekimuファイル群(競争・随意 各1年度分)を対象に
行抽出→既存`raw_contracts`投入→抽出検証レポート、まで。
